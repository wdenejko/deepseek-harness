# Agent Note: control remote local-model servers from the model dropdown

Status: implemented

English | [中文](2026-08-22-local-model-lifecycle.zh.md)

## Problem

A workstation deployment reaches self-hosted `llama-server`-style model servers on a remote host, each launched by a `run-*.sh` script that serves one model on a shared port. The harness reached them only through a single `llm-pi-ai` provider whose settings listed one model, so the model dropdown could neither enumerate the other models, show which one was running, nor start/stop them. Switching models meant SSHing to the host by hand.

The shaping fact: `llama-server` serves one model at a time on its port and effectively ignores the requested model id, and the local llm route validates only its single configured model id. So "which script is running" is a *lifecycle* axis, not an llm-routing axis — every local script routes to the same configured llm selection. A model's identity is a handle for *which server process to run*, not a distinct routable model.

## Decision

Three layers plus an opt-in mount.

**Seam + SSH implementation — `@deepseek-ai/dsh-local-models`.** A `LocalModelManager` service registers `ctx.localModels` with `list`/`status`/`start`/`stop`. Discovery, start, and stop are each one `ssh <target> '<remote command>'` driven through `ctx.subprocess` behind a `RemoteRunner` seam (so orchestration is unit-testable without a real subprocess or network); run-state is a plain `fetch` of `${probeBaseURL}/health` and `/v1/models`. `start` stops the current server first (only one fits the port), launches the script detached (`setsid nohup … </dev/null &`) so it survives the SSH session close, and marks the model `starting`. That `starting` window is computed lazily from a launch timestamp against `startTimeoutMs` on each `list`, so there is no background timer to own or dispose. A start or stop emits `localModels/state-changed`, a payload-free forwarded event (declared in the seam's `types` submodule) that mirrors `llm/adapters-updated`. The Service Definition and its single provider live in one package: the capability-seam rule keeps them together until a second transport (systemd, remote HTTP) exists. All host/endpoint facts are validated `Config` fields read live through the settings section, including the `route` (the llm selection to activate once a server is up) and the `stopCommand`.

**Host RPC — `localModels.*` in `dsh-host-apiproxy`.** A thin domain (`list`/`start`/`stop`) mirrors the optional-service `goals`/`jobs` pattern: it reads `ctx.get('localModels')` and returns a **null catalog** for `list` when the seam is not mounted (the opt-in-absent signal the client reads to render nothing), and the `local-models-error` branch for a transport failure or an absent seam on `start`/`stop`. The wire vocabulary is the seam's own types, imported type-only from `dsh-local-models/types` and re-exported through the contract to the client.

**Dropdown — a "Local models" section in `ui-model-selection`.** The per-session `ModelDirectory` gains a local catalog axis (`loadLocal`/`startLocal`/`stopLocal`, its own generation guard) alongside the llm catalog; the composer service subscribes to `localModels/state-changed`. `ModelSelect` filters out the plain llm group whose id is the local `providerId` (the lifecycle section supersedes it) and renders the discovered models with run-state badges, a Stop control on the running one, and select-to-start: picking a stopped model calls `startLocal` (which routes the session to the catalog's `route` on success) and picking the running one just closes. While a model is `starting` and the menu is open, the component polls `loadLocal` so the badge advances to running. The trigger labels itself with the running local model when the session is on the local route.

**Display name from the script.** A discovered model's dropdown name is composed from the script itself, not its opaque slug: the leading segment of the second-line header comment (trimmed at the first spaced dash or sentence break) followed by two optional header tags — `# drafter:` (the speculative drafter label, e.g. `DFlash 2`) and `# nudge:` (whether the nudge patch is active, on/off) — joined with ` · `. An untagged script falls back to the comment alone, then its alias, then its slug, and the full header comment rides along as `LocalModelEntry.description` for a hover tooltip. Drafter and nudge are read *only* from these explicit tags because they cannot be inferred reliably: across the real host's scripts the drafter is encoded inconsistently (`--spec-type draft-dflash` denotes DFlash 1 or DFlash 2 depending on the build), and the nudge patch shows only as a substring of a build/toolbox path, so auto-detection would mislabel. The user opts in per script by adding the two tag lines; the harness composes the rest.

**Opt-in.** The package is not added to `dsh-base`. The apiproxy domain is inert without the seam, and the dropdown section renders only when `list` returns a catalog, so other deployments are unaffected. A deployment enables it by mounting `@deepseek-ai/dsh-local-models` in its own profile with the host config.

## Alternatives considered

**Register every discovered model into `ctx.llm` under the local provider.** Rejected: the llm route validates `selectModel` against its catalog, so arbitrary discovered ids would need catalog membership, and since the endpoint ignores the model id all entries route identically anyway. Routing every local selection to the single configured llm entry, with the lifecycle section owning per-script identity and run-state, keeps the llm catalog honest and needs no cross-plugin settings write.

**Overload `session.selectModel` to start a server as a side effect.** Rejected: session selection stays a pure routing verb; lifecycle belongs to its own seam. The client composes the two — start, then select the route — rather than the host coupling them.

**Track `starting` with a background readiness poll on the host.** Rejected in favor of a lazily-computed timestamp: a launched model reads as `starting` until the next `list` sees it up or the budget elapses, so the seam owns no long-lived timer, and clients drive the transition by polling `list` while a start is in flight (plus the change event for cross-client convergence).

**Split the seam into Definition and Provider packages now.** Deferred: there is one transport (SSH). The systemd and remote-HTTP transports offered during design are the future split point; splitting before a second provider exists is the premature-abstraction the capability-seam rule warns against.

## Consequences

Out of the box nothing changes: the feature is opt-in and absent from shipped defaults. Where mounted, the dropdown lists every `run-*.sh` (`.bak` excluded), badges the running one, and starts/stops from the menu; the plain local llm group is hidden in favor of the lifecycle section, and a start routes the session to the configured local route. The seam requires passwordless SSH and one model per endpoint; a script with a computed `--alias` has its run-state attributed only to a start this seam issued. The `local-models` package carries full unit and settings coverage; the apiproxy domain has present/absent/error tests; the dropdown has render/interaction tests. The client GUI files (`ModelSelect.tsx`, `directory.ts`, `service.ts`) sit under the existing `vitest.config.ts` client-coverage exemption, and `api-proxy.ts` under its own, so those layers are behavior-tested rather than per-file gated. A real-composition web e2e (`apps/web/tests/local-models-dropdown.e2e.ts`) boots the assembled web app against the seam with a fake `ssh` executable and a local HTTP endpoint double standing in for the remote host, then drives the dropdown through discover → start → stop, asserting the run-state badges and a golden section render. Building it surfaced two gaps, now fixed: the opt-in package must be an `apps/cli` dependency (`workspace:^`) so a profile can mount it — installed but absent from every default bundle, exactly like `tool-cordis` — and `ModelSelect` must refresh the local catalog on mount and on open (`loadLocal`, mirroring the llm `load`), because the section otherwise never populates for a session directory created after the connect-time reset. Live smoke against the real host — which starts and stops real model servers — is the remaining validation.
